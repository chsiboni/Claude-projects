# Fizikal CRM — monday.com

CRM שמרכז את הלקוחות של Fizikal: מי משלם לנו, איזה סניפים יש להם, ומי אנשי הקשר.

**לקוח = מי שמשלם לנו** — מי שמופיע בדוח הנהלת החשבונות, לא כל חברה שרשומה במערכת.
**המצב הנוכחי חשוב יותר מהיסטוריה.** הסיווג נקבע לפי **הריטיינר החודשי בלבד**, לא לפי סה"כ ולא לפי קניות חד-פעמיות.

```
לקוח (ח.פ) → סניפים → אנשי קשר
```

## מה כאן ומה לא

הריפו מכיל **קוד וקונפיג בלבד**. הנתונים עצמם — ח.פ, סכומי כסף של 400 לקוחות,
טלפונים ומיילים של אלפי אנשים — **לא נכנסים לגיט**. `data/` ו-`out/` ב-gitignore.

הקונטיינר של כל סשן הוא ephemeral, כלומר הקבצים נעלמים בסופו. זה בסדר:
הדוח החשבונאי הוא חודשי, ולכן ממילא מעלים אותו מחדש כשהוא מתעדכן.

## קבצי קלט (להעלות ל-`data/`)

| קובץ | נדרש עבור | תדירות |
|---|---|---|
| `הכנסות <חודש>.xlsx` | Tier, סכומים, רשימת ההשלמות. **בלעדיו אין pipeline.** | כל חודש |
| `רשימת סניפים.xlsx` | הצלבת ח.פ ↔ קוד חברה, שכבת הסניפים | פעם אחת |
| `רשימת עובדים.xlsx` | שכבת אנשי הקשר | פעם אחת |

## הרצה

```bash
pip3 install -r requirements.txt

# דוח חדש? קודם לאמת שהפריסה לא זזה
python3 src/revenue_pipeline.py --inspect

# הרצה מלאה
python3 src/revenue_pipeline.py --month 2026-06
```

הפלט: `out/clients_<חודש>.xlsx` לייבוא ל-monday, ו-`.json` להשוואות בין חודשים.
הסקריפט מדפיס את התפלגות ה-Tier ומשווה אותה לזו שאומתה ביוני 2026 (404 לקוחות) —
סטייה גדולה היא סימן שמשהו בדוח או בסינון השתנה.

## קונפיג

כל ההחלטות העסקיות יושבות ב-`config/`, לא בקוד. ההסברים בשדות `_comment` / `_note`.

| קובץ | תוכן |
|---|---|
| `revenue.json` | פריסת הדוח, כלל הסינון, קיטלוג סעיפי ההכנסה, טווחי Tier |
| `nets.json` | רשימת הרשתות המאושרת |
| `monday.json` | מזהי בורדים, עמודות וקבוצות + מלכודות ה-API |

### שתי מלכודות ששוות את הקריאה

**שורות סיכום.** הדוח מערבב שורות לקוחות עם שורות סיכום חשבונאיות. בלי סינון
הסכומים מנופחים פי 2 ויותר (23.5M במקום ~7.5M). הקו הראשון הוא פילטר הסאפ:
לקוח אמיתי הוא `2xxxxx`, וזה זורק גם את הטבלה המסכמת בתחתית הגיליון.

**רשתות.** רשת גדולה לא חולקת ח.פ אחד — לכל סניף ח.פ נפרד (ספייס = 14 ח.פ),
ואין בדוח שום עמודה שמזהה רשת. לכן האיחוד נעשה לפי `nets.json` בלבד.
זיהוי אוטומטי לפי "מילה ראשונה משותפת" **נוסה ונכשל** — הוא תפס מתנ"סים ועסקים
עצמאיים ("החברה" = 13 גופים שונים, "מרכז ספורט", "פילאטיס"). אל תנסה שוב.

מאותה סיבה גם **לא מצליבים לקוחות לפי שם**: הצלבה כזו נתנה 80 התאמות שרבות מהן
שגויות בעליל ("לה פילאטיס" → "בשביל הפילאטיס", "בי פיט" → "E FIT"). כסף לא מיוחס
לפי ניחוש שם — 171 הלקוחות שלא הוצלבו נכנסים לבורד השלמה ידנית.

## מפתחות קישור

- **ח.פ** — הגוף המשפטי, מפתח הקיבוץ של בורד הלקוחות.
- **מספר סאפ** — כרטיס חיוב. סאפ→ח.פ הוא 1:1 (מזהה בטוח), ח.פ→סאפ הוא 1:רבים.
  אנלוגיה: ח.פ = שם משפחה, סאפ = כרטיס אשראי. למשפחה אחת יכולים להיות כמה כרטיסים.
- **קוד חברה** — המזהה הפנימי של Fizikal, הקישור בין בורד הסניפים ואנשי הקשר.
